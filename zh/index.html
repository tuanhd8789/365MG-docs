Microsoft 365 ↔ Google Workspace 迁移

迁移整个公司的 Microsoft 365，不丢失任何一封邮件

365MG 从您自己的 Windows 电脑，在 Microsoft 365 和 Google Workspace 之间双向复制邮件、联系人、日历、OneDrive 和 Google 云端硬盘、共享云端硬盘以及组。它为每个项目记录日志，再次运行不会产生重复，并且在任何可能导致数据丢失或重复的选择前都会停下来询问您。

功能

🏢

Microsoft 365 和 Google Workspace

可连接任意数量的 Microsoft 365 租户和 Google Workspace 帐户，然后按任意方向复制：Microsoft ↔ Google、Microsoft → Microsoft、Google → Google。

🧭

引导式迁移任务向导

用筛选器选择源用户，自动将其匹配到目标用户，批量设置目标域和许可证，并创建缺少的用户。

✉️

邮件、联系人、日历

通过 Exchange 邮箱 API 逐个文件夹导出并导入每个项目，每个项目都有日志，中断的运行会从停止处继续。

☁️

带哈希校验的 OneDrive

复制文件和文件夹，保留创建和修改日期，用 quickXorHash 校验每个文件，并以可续传的 64 MB 分段下载大文件。

👥

邮件组

将通讯组列表和启用邮件的组重建为具有相同别名、成员和所有者的 Microsoft 365 组。

🌊

批次和试运行

将用户分成多个批次，在不写入任何内容的情况下统计一次运行将复制的数量，然后正式复制，并按计划持续同步直至切换。

✋

先询问，不猜测

目标邮箱或 OneDrive 缺失、用户被重新创建、项目结果未知：每种情况都会进入“待您决定”列表，并附上解决它的操作。

📊

报告

按用户和总计对比源与已复制数量，列出需要查看的用户、组和备注；可导出独立的 HTML 页面或 CSV。

🌐

九种语言

English、Tiếng Việt、简体中文、한국어、日本語、Deutsch、Русский、हिन्दी 和 العربية（从右到左）。

迁移流程

  1. 连接两个云平台以 Microsoft 全局管理员或 Google 超级管理员身份登录；365MG 检查权限并设置其数据迁移应用。
  2. 规划迁移任务选择用户、匹配目标，选择内容、线程数和计划。
  3. 准备目标一键创建缺少的用户并分配许可证。
  4. 先试运行，再复制先计数，再逐批复制；可随时暂停和继续。
  5. 决定并生成报告处理需要您决定的事项，持续同步直至切换，导出报告。

源自真实迁移的经验

每一项保护措施都来自一次 350 名用户的公司迁移中出过的问题：中途失去许可证的邮箱、尚不存在的 OneDrive、发送过程中断开的连接。

  • 每个项目在发送前都会记入日志：中断的运行会继续，而不会重复。
  • 结果未知的项目绝不会被悄悄重新发送：由您决定。
  • 除非您允许，否则不会复制到已有邮件的目标邮箱。
  • 数据只经过您的电脑；临时文件存放在您选择的驱动器上，上传后立即删除。
  • 更新经过签名：应用只安装作者签名的版本。
